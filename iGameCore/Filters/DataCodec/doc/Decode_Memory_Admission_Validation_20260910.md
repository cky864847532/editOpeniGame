# 解码工作容量准入验证记录

## 实现范围

本次实现依据 `Decode_Memory_Admission_Implementation_Plan.md`，基线为 `71f5a6941`。验证平台为 Windows x64，构建配置为 Release，CMake/Ninja 与 UCRT64 Clang++。加载环境脚本 `clion_env.ps1` 后执行构建。

同一 `ResidentByteBudget` 覆盖必要长期存储、字段窗口、阶段工作区、完整在途块及受控闲置 backing。块工作容量在输入正文读取前与槽位联合取得。输入、输出、临时区具有独立 backing；视图使用固定容量；worker 使用已预约范围。计数与计算额度分别限制在途块数、活跃计算数。

必要全内存目标在 driver 阶段边界准备。固定模式容量不足在排空、回收后失败。自适应模式使用现有内部恢复机制与等待期限。系统分配失败、工作区越界、读取或提交失败进入现有 failure 和清理链。编码继续使用已有缓冲入口，公共执行设施的接口适配包含编码回归验证。

## 各路径的实际实现

| 路径 | 固定区域与生命周期 |
| --- | --- |
| 普通数值、整数 residual、多分量 | 独立压缩输入与完整输出；分量和 residual 位于临时 arena，逐分量复用 |
| Layered residual | 完整背景输出保留；各层残差与分量工作区按最大必要层复用 |
| Affine、Predictor、时间与属性参考 | 完整依赖缓存预先就绪；目标参考区保留，准备窗口与后续计算临时区复用 |
| Wavelet | 压缩 blob 使用输入子视图；浮点仅保留 ceil(N/2)、floor(N/2) 两份 double residual；整数保留两份 floor(N/2) 的 uint64 residual，逐对计算参考变换与重建，奇数尾使用栈变量 |
| 几何 | 原始数值结果与必要的 Float32 转换结果共用输出 backing 中的独立范围 |
| 普通拓扑 | 四段输入、四类完整输出、cellSizes、grammar offsets；提交 offsets 窗口复用计算后的临时区 |
| 字段流 | Raw 输出窗口；Zstd 输入和输出窗口；窗口跨块复用并随 reader 释放 |
| 多面体 | 顺序解码工作区由阶段持有；提交前扫描 count cache 得到批次形状，再预约完整输出与临时区 |
| 最终回放 | 连续存储直接借用；范围回放在 driver 上准备固定窗口 |
| Observer | 独立输出 owner 连同只读视图移交；记录 transferred 事件并退出 DataCodec 预约及自有分配统计 |

最低额度统一为 `minimumExecutionLimitBytes`。分析器和运行时调用同一块布局函数，沿实际依赖与提交顺序计算同一时刻的长期存储、阶段缓冲、单块工作容量峰值。普通数值和普通拓扑分析使用元数据。多面体提交扫描三条计数流；外层 Zstd 需要解压对应前缀，有界读取可能预取相邻字节，ID 值不参与解析。

边界：宿主提供及已移交的结果、第三方内部内存、线程栈、Params 和清单外元数据豁免。分析结果适用于约定的全内存单块推进路径。分析阶段的临时缓冲独立于实际解码预约。整进程物理内存具有独立边界。

## 集中验证命令与口径

构建目标：`iGameDataCodecTests`、`iGameDataCodecFileBenchmark`。核心回归采用 `ctest -R 'DataCodec\.(All|StorageAnalysis)$' --output-on-failure --timeout 180`。

真实文件使用 `iGameDataCodecFileBenchmark --storage-bound <input.igc> <deltaMiB> <workers>`。解码包含入口检查、数据展开和宿主结果组装；分析时间单列。受控容量通过真实预约账本验证，物理内存通过 Windows 进程采样记录。较大线程上限下，各阶段可用余额不同，整次请求的峰值槽位数可以大于一。

输入 IGC 为 `car_3800W_analysis_adaptive_20260910-113653.igc`，2,204,353,773 字节；对应源 CGNS 为 10,571,784,552 字节。结果规模为 8,034,973 点、39,494,600 单元、131 属性、1,052,581,463 属性值。

小型测试校验确定结果、精确预约峰值、最低额度减一字节的拒绝、资源释放；真实文件边界运行校验流程完成及结果规模。真实文件测速中的 `shape_matches` 只表示结构规模匹配；数值误差与整数精确性由对应核心测试覆盖。

## 验证结果

Windows Release 构建通过。集中回归结果：

| 测试 | 结果 | 耗时 |
| --- | --- | --- |
| `DataCodec.All` | 通过 | 14.85 s |
| `DataCodec.StorageAnalysis` | 通过 | 0.69 s |

机制用例中，128 字节额度、4 计算额度、2 槽位的实际峰值为 1 块、1 活跃计算；384 字节额度下达到 2 块、2 活跃计算。两者均顺序提交完成，结果移交后由调用方继续持有，DataCodec 最终预约与实际自有分配归零。

新增不均匀多面体用例包含 65,537 个 cell，完整批次每 cell 四个 face，尾批次 cell 九个 face。分析与实际预约峰值均为 13,631,664 字节，单计算与较大计算上限均通过。减少一字节时在必要批次准入前失败。

覆盖的机制包含：lease 拆分与合并、跨预算拒绝、输入前联合准入、延迟队首、容量释放发生在等待前、字节等待取消、运行时降低和提高上限、工作区越界、布局运算溢出、读取失败、worker 异常、observer 失败及异常清理。自动控制器测试通过模拟时钟验证首块字节等待增长和压力恢复条件。

独立真实文件运行均使用完整属性解码与宿主 adapter：

| 运行 | 容量上限（字节） | 分析 | 解码 | 峰值槽位 / 计算 | 字节等待 | 结果 |

| 最低额度，1 计算额度 | 1,078,738,245 | 17.1766 ms | 35.4365 s | 1 / 1 | 0 s | 完成 |
| 最低额度，4 计算额度 | 1,078,738,245 | 16.9193 ms | 21.0197 s | 5 / 4 | 16.7354 s | 完成 |

成功运行的受控峰值均为 1,078,738,245 字节；三次运行结束的预约均为零。峰值阶段为 `topology-block`。该普通拓扑文件无需多面体计数扫描。

单计算运行记录 8,488 次缓冲复用、42,035 次受控实际分配；4 计算运行记录 9,079 次复用、41,444 次分配。复用统计记录 backing 从池中取出的次数，实际分配次数取自预算的分配记录。单计算仅有一个槽位，任务通过槽位等待推进，该配置的字节等待为零。

4 计算运行的 Windows 进程生命周期峰值工作集为 12,554,588,160 字节，解码结束时 private bytes 为 9,543,553,024。宿主完整结果在解码结束后仍然存活，受控额度不包含这些输出。该物理占用数据明确区分于 1,078,738,245 字节的 DataCodec 受控峰值。

拒绝运行使用现有 `DecodeMemoryAdmission` failure，携带必要申请量、已预约量、当前上限及允许上限；最终已释放受控预约。小型测试使用减一字节验证边界，大文件命令使用减一 MiB 验证失败路径。

以上为各配置单次运行记录，文件缓存与系统负载影响耗时。

编码回归使用相同源 CGNS、默认自适应模式、全部属性、无损数值配置：读取 CGNS 25.836 s，编码并写出 IGC 24.415 s，编码 CPU 时间 141.891 s。随后释放源模型，独立解码新 IGC 耗时 9.005 s，无缓存命中，`shape_matches=1`。

新文件为 `car_3800W_decode_admission_20260910-2310.igc`，2,204,353,773 字节。历史样本保持原状，两份文件的字节数相同；本次未执行文件逐字节比较。

历史单次自适应样本为编码 26.421 s、解码 7.513 s。本次单次结果的编码耗时下降约 7.6%，解码耗时上升约 19.9%。这两组结果缺少重复配对采样，当前记录用于呈现实际回归结果，性能变化的稳定性与具体成因尚未单独验证。本次目标是确定工作容量准入及最低额度运行保障。

## 验证中修复的问题

- 单记录流的批次描述必须等待前一批提交更新游标，多面体跨固定批次测试覆盖该约束
- 诊断快照使用 try-lock，机制测试采用有期限的重试读取，避免将瞬时锁竞争判断为流程失败
- 字段流测试预算覆盖实际窗口，完整 payload 测试分别验证阶段窗口峰值与展开后保留量
- Wavelet 审计断言对应实际存在的两份 residual，已删除的数组保持未知项为空
- 参考算法测试使用运行时布局生成的固定 arena，覆盖该路径的真实工作区容量契约
- 必要目标的容量等待保持原申请者和并存对象信息，拓扑事务、多面体索引及 Morton 诊断回归验证这些信息与失败回滚
- 删除已经无生产调用的旧几何和属性参考准备函数，解码参考工作区统一由预备视图实现

历史报告保持原有数据。WASM 构建、浏览器运行与 WASM 占用审计未纳入本次验证。
