# 解码工作内存准入与最低运行额度实现方案

## 1. 状态与目标

本文以提交 `71f5a6941` 为代码阅读基准，描述后续实现方案。该提交已经完成原有必要自有存储的下界分析。本文新增的块级工作容量准入与扩展下界属于待实现内容。

本次完整接入范围是解码。公共执行设施继续服务编码，编码调用点随公共接口调整进行必要适配。本次新增的最低运行额度计算针对解码。

目标如下：

1. 内存上限和计算线程上限共同约束任务运行
2. 内存不足以容纳更多在途块时，由准入机制自然减少实际并行任务数
3. 已准入任务拥有推进至释放点所需的工作容量
4. 下界分析和运行时分配共用确定的容量与生命周期规则
5. 复用现有资源根、字节预算、块流水线、failure 和诊断设施

完成标准：设置足够的最低额度后，较大的计算线程上限可以保留；解码通过字节准入自然减少同时处理的块数，并持续推进至完成。

本文中的保障限定于清单内受控容量和内部准入。宿主内存、第三方内部内存、系统实际分配失败及整进程物理内存均有独立边界。

## 2. 资源上限与分析结果的定义

| 参数或结果 | 实现后的含义 |
| --- | --- |
| `ownedStorageLimitBytes` | 清单内长期存储、阶段工作缓冲、在途块工作缓冲和受控闲置缓冲共同使用的容量上限 |
| `computeLimit` | 同时执行计算的额度上限 |
| `slotLimit` | 从读入到消费完成的在途块数量上限 |
| `minimumExecutionLimitBytes` | 唯一的最低额度结果，表示包含必要存储与工作缓冲后，按约定顺序、一次推进一个块所需的受控容量峰值 |

删除 `minimumOwnedStorageLimitBytes` 结果字段、旧口径的独立汇总逻辑，以及仅用于维持旧结果的接口和分支。对外只提供 `minimumExecutionLimitBytes`，调用方统一迁移到这一结果，不保留旧字段别名或双结果兼容路径。

复用仍然有效的存储容量公式、依赖分析和生命周期模拟，将其扩展到唯一的最低执行额度定义。必要存储容量作为计算过程和峰值诊断的组成部分，不再作为另一套最低额度结果发布。

`computeLimit` 和 `slotLimit` 都是上限。仅准入一个块时，允许其余计算额度空闲。新下界不乘以设置的线程数。

删除 `ValidLimits` 中 `slotLimit >= computeLimit` 的限制。保留计算额度、槽位额度各自的合法范围、执行根预置记录容量上限，以及无线程平台的单计算额度约束。允许 16 份计算额度配合 2 个在途槽位。

最低运行额度采用一条明确支持的执行路径：按现有依赖和叶处理顺序推进，块级流水线一次推进一个块，多面体提交采用本文约定的固定批次。该值表示这条路径的容量门槛，不执行全局最优调度搜索。

基础粒度继续使用当前固定定义：新编码基础块为 `kSpatialBlockElementCount`，当前值为 65536；范围读写窗口为 `kIoWindowBytes`，当前值为 1 MiB。解码按文件记录的实际块布局计算，旧文件的大块继续遵守既有 `singleRecord` 约束。

## 4. 公共容量机制

### 4.1 一份容量账本

继续使用 `ResidentByteBudget` 的共享状态。新增工作缓冲从同一预算取得 lease，不增加第二份工作内存预算。

总预约量为：

`长期存储预约 + 阶段缓冲预约 + 各在途块预约 + 闲置缓冲预约`

分类只用于诊断和生命周期处理。各模块不设置比例配额，也不预留相互独立的固定额度。

预约成功增加容量承诺；实际数组分配成功增加实际分配记录。数组中的多个视图不重复计数。

### 4.2 Lease 转移与唤醒

在现有 lease 中增加内部拆分、合并和转移能力，要求：

1. 只能在同一预算 state 内拆分、合并和转移
2. 操作前后总预约量守恒
3. 零容量、移动后对象和重复释放具有明确状态
4. 已承诺容量内部的使用不再次向全局预约
5. 归还容量后唤醒等待资源变化的 driver

当前 `Lease::Reset()` 只减少计数。新增通知应在容量锁释放后执行，通过弱引用连接执行根，避免引用环。

容量通知需要推进资源事件代次。driver 使用“读取代次、检查准入条件、按代次等待”的既有模式，保证释放发生在检查与等待之间时也能被观察到。

### 4.3 锁和析构规则

统一锁顺序为：执行状态、容量状态、缓冲池状态。需要多把锁的操作遵守这一顺序。

数组析构、用户回调、failure 发布和唤醒放到相应资源锁外执行。lease 析构先完成容量计数变更，再通知执行根，不持有容量锁反向获取执行锁。

## 5. 块工作容量与工作缓冲

### 5.1 `DecodeBlockMemoryPlan`

新增内部块工作布局描述，包含：

- 当前块身份和工作类型
- 输入区域容量
- 输出区域容量
- 临时区域容量
- 各数组的元素类型、元素数、对齐和区域偏移
- 各计算阶段允许复用的临时区域布局
- 三个区域的合计预约量

布局生成只使用块元数据、reference 形状和确定的执行路径。所有乘法、加法、对齐和平台大小转换都检查溢出。

分析器和真实执行调用同一个布局生成函数。按帧、叶和属性汇总的生命周期逻辑继续留在 `DecodeStoragePlan`。

### 5.2 `DecodeBlockWorkspace`

新增内部工作缓冲所有者，持有输入、输出、临时三个定长区域以及对应预约。三个区域使用独立 backing，方便结果独立移交和缓冲复用。

读入、计算、提交通过有界视图使用区域。组件循环和残差层循环复用指定临时空间；同时存活的数组使用互不重叠的区间。相互独立的计算阶段可以复用同一临时区域，区域容量取这些阶段布局的最大值。

初版以块生命周期为工作容量持有边界：从读入前成功准入，持续至提交和消费完成。不引入计算过程中分段补额度的协议。

清单内数组不再通过向算法暴露可自由扩容的 `vector&` 决定容量。相应解码函数改为填写调用方准备的范围。缓冲超出计划、形状不符、计划与路径不匹配时直接记录 failure。

共用数值算法接受缓冲视图；编码调用方继续负责准备其工作缓冲。资源准入留在流程层，不放进第三方编解码器，也不放进通用数值运算内部。

## 6. 各解码模块的容量规则

记号：`N` 为当前数值块元素数，`C` 为分量数，`V` 为原始标量字节数，`E` 为当前压缩块字节数，`K` 为当前拓扑块 cell 数，`I` 为当前拓扑块 connectivity 元素数。以下容量均需加入共享布局函数计算出的必要对齐。

| 路径及入口 | 工作缓冲 | 计算与生命周期 |
| --- | --- | --- |
| `NumericDecodeCursor`、`ReadNumericArrayBlockPayload` | 压缩输入 | `E`，来自块布局，读入到块退休期间持有 |
| 普通数值解码、`DecodeNumericArrayComponentBundle` | 完整块结果、单分量结果 | `N×C×V` 和 `N×V`；组件顺序处理并复用单分量区 |
| 整数 literal/run 解码 | `uint64_t` residual | 当前分量元素数乘 `sizeof(uint64_t)`，覆盖与分量结果并存的区间 |
| Layered residual | 背景结果、当前层残差、分量结果 | 背景为 `N×C×V`；残差按各层最大 `refinedElementCount×C×V` 准备，逐层复用 |
| Affine、Predictor reference | reference 范围、重采样或移位准备、解码结果 | 根据实际 reference 路径布局，完整 reference 缓存归长期存储 |
| 浮点 Wavelet | reference 范围、分量提取、low/high、delta、重建 | 临时标量按 `double` 计算，组件顺序复用 |
| 整数 Wavelet | reference low/high、residual low/high、恢复 low/high | 按 `floor(N/2)` 和 `uint64_t` 计算，奇数尾单独处理 |
| `ComputeGeometryDecodedBlock` | 数值结果、Float32 转换结果 | 原始结果 `N×C×V`；需要转换时增加 `N×C×sizeof(float)`，覆盖两者并存 |
| 普通拓扑输入 reader | 四段压缩输入 | 使用 connectivity、cell size、polynomial order、cell type 的记录字节数 |
| `DecodeConnectivityTopologyBlock` | connectivity、offsets、cell types、polynomial orders | 使用 `CalculateDecodedConnectivityStorageSize` 的块级结果 |
| 普通拓扑辅助计算 | cellSizes、grammar cellOffsets、adjustedOffsets | 分别按 `K×sizeof(IndexType)`、`(K+1)×sizeof(size_t)` 和固定提交窗口计算，按阶段复用 |
| 多面体顺序解码 | 字节窗口、索引写出窗口、计数验证窗口 | 按固定窗口和真实尾窗口计算，由 heavy phase 持有 |
| 多面体提交 | 批次 offsets、unique IDs、local IDs、计数窗口 | 由准入前生成的批次描述确定 |

### 6.1 Reference 准备

父属性和时间参考的完整缓存必须在目标块准入前准备完成。保留 `DecodeSingleAttributeRangeToCache` 当前先准备依赖、再 Begin 目标字段、最后启动块流的顺序。

重采样工作布局覆盖目标 reference 范围、源读取窗口和左右 tuple 暂存。Predictor 布局覆盖必要源范围与移位输出同时存在的阶段。准备完成后的 reference 区域继续保留至参考解码完成；准备阶段临时区可以与后续计算临时区复用。

### 6.2 Wavelet

浮点 low/high 长度分别为 `ceil(N/2)`、`floor(N/2)`。临时数组宽度按真实实现使用的 `double` 计算，不能直接使用输入标量宽度代替。

当前 `ReadBlobWithLength` 复制 low/high blob。增加解码专用的只读子视图读取函数，直接借用已由当前块持有的压缩输入。移除解码路径中的这些 blob 复制数组，保留长度、边界和尾随数据验证。

### 6.3 普通拓扑

`ConnectivityTopologyDecodeInputReader` 已提供四段连续输入。生产路径中的 `LoadConnectivityEncodedStream` 使用这些视图，不再申请同一输入的复制数组。

grammar 的 `cellOffsets` 使用 `size_t`，需要按当前目标平台的真实宽度计算。固定 cell 类型路径仍包含当前 grammar 所需的 offsets 工作数组。

提交时的 adjustedOffsets 只使用固定窗口，可以复用已结束的计算临时区。提交开始前该空间已经获得容量保障。

## 7. 字段、长期存储与最终提交

### 7.1 字段窗口

`FieldDecodeStreamReader` 的输入输出窗口跨越多个块，由字段作用域持有预约。

- 原始字段读取准备必要读取窗口
- 外层 Zstd 字段准备输入、输出两个窗口
- 属性完整展开先准备 `rawSize` 存储和展开窗口，再启动终端工作

`PrepareLeafPackageFieldPayload` 展开完成后释放窗口，完整 payload 保留到对应属性处理结束。字段作用域移交和销毁需要一起处理窗口、reader 和预约。

### 7.2 必要长期存储

继续使用当前几何缓存初始化、`BeginAttribute` 和拓扑 sink 初始化。由 driver 在阶段边界准备完整目标。

块计算和提交只填写既有范围，不在 worker 中增长必要长期目标。多面体的五个完整索引目标继续在终端解码前准备。

阶段准备之前保证上一块流已经排空。必要目标申请不足时按第 9 节处理，不能等待本阶段尚未开始的后继操作释放自身所需容量。

### 7.3 最终提交

`ReplayTypedDecodedCache` 能提供连续视图时借用原存储；需要范围读取时，在提交开始前准备固定窗口。

在分析器中按照实际顺序记录提交：几何提交及释放、拓扑提交及其保留或释放、属性提交。工作容量与必要存储的并存按这些事件计算。

## 8. `RunOrderedBlocks` 的联合准入

### 8.1 新的描述回调

增加描述下一个块工作容量的回调。回调不读取压缩正文、不推进输入游标，只生成下一块的 memory plan。等待期间保留该计划，成功读入后再推进游标。

多面体批次通过其计数描述提供 plan，按第 11 节处理。

### 8.2 Driver 循环

1. 消费队首已成功完成的结果，完成提交与槽位确认
2. 销毁或移交输出，释放输入和工作缓冲，归还预约与槽位
3. 服务取消、限额变化和缓存回收事件
4. 生成并保存下一块的工作布局
5. 联合尝试取得一个槽位和该块完整工作容量
6. 成功后建立 workspace、读入块并发布计算任务
7. 暂时无法准入时继续处理已有记录，并等待明确资源变化

槽位与字节容量作为一个成功结果发布。字节不足不保留槽位，不消耗块序号，不读取正文。

保留现有工作类型切换前排空流程的规则。

### 8.3 准入结果

| 结果 | 行为 |
| --- | --- |
| 已准入 | 读入并发布计算任务 |
| 等槽位 | 消费已有结果，等待槽位归还 |
| 等字节 | 消费已有结果，回收可选缓冲，等待容量归还 |
| 等压力恢复 | 进入现有压力等待状态 |
| 最低需要超过允许额度 | 记录容量 failure |
| 已取消或停止 | 进入现有清理流程 |

暂时性字节等待作为正常流控状态记录，不发布终止性容量 failure。

### 8.4 Worker 与顺序提交

worker 只使用该块已获得的工作容量。禁止为本块必需的清单内数组追加全局额度等待。worker 不等待同一线程池中的子任务。

后续块只能使用其独立完整预约，不能占用队首块已经承诺的空间。队首完成后由 driver 消费，整个流水线可以在一个在途块的容量下推进。

复用 `RunDrainGuard` 和 `BlockRecord::Retire()`。异常路径先等待工作停止访问块记录，再释放输入、输出、workspace 和槽位。

## 9. 容量不足与失败规则

存在在途块时，字节不足可以等待其退休。driver 持续消费已完成的队首结果。

排空后先回收明确可释放的闲置 scratch 和可选缓存，再重新检查一次必要容量。

| 条件 | 确定处理 |
| --- | --- |
| 固定模式，排空和回收后仍不足 | 立即 failure |
| 自适应模式，必要量超过允许的最终上限 | 立即 failure |
| 自适应模式，当前目标较低且控制器仍可上调 | 有期限地等待容量恢复，复用现有超时机制 |
| 系统实际数组分配失败 | allocation failure |
| 布局容量不足、形状不符、溢出 | 对应验证或内部契约 failure |
| 读入、解码或提交失败 | 使用现有首错和取消收束机制 |

终止性容量报告包含当前必要保留量、下一工作单元需求、当前上限和允许上限。禁止让一个在当前配置下永远无法准入的任务无限排队。

已存在的文件存储能力继续受原有后端规则约束。块级输入、输出和临时工作区域使用内存。新的全内存下界不计入 spill 带来的容量降低，也不在计算错误或实际分配失败后通过切换后端掩盖问题。

## 10. 闲置缓冲复用

在现有 `ScratchByteBufferPool` 内增加受控定长缓冲入口。解码工作区域使用该入口，不增加独立缓冲池管理器。

闲置数组携带 lease，持续占用总额度。再次使用时将数组和 lease 一起移交 workspace。

受控入口只复用容量和对齐匹配的数组。一次块准入先选取可复用区域，再为缺少的区域预约容量，全部成功后发布结果。失败时不留下半个已准入块。

同一数组在闲置与活跃状态之间转移不重复增加预约量。需要释放空间时优先释放不匹配的闲置数组。保留现有数量上限和单块留存上限作为缓存规则，不分配固定比例。

公共池中原有编码缓冲的适配必须明确区分调用路径。解码清单内数组全部走受控入口，禁止通过默认参数漏回旧的可自由扩容入口。编码活跃工作集的全面接入不作为本次解码下界承诺的一部分。

## 11. 多面体批次描述

### 11.1 当前需要改变的位置

`BuildPolyhedronCellBatch` 当前在 worker 中读取计数并决定输出数组大小。将批次形状计算移到字节准入之前。

新增轻量批次描述，记录起始 cell、face、unique ID、local ID 偏移，本批四种数量，以及输出和临时区域容量。

批次最大 cell 数沿用当前 `kSpatialBlockElementCount`。描述生成只扫描 count 数据，不读取 ID 正文。

### 11.2 批次容量

本批 cell、face、unique ID、local ID 数分别记为 `K、F、U、L`。

输出索引数量：

`2×(K+1) + (F+1) + U + L`

乘 `sizeof(IndexType)`，加上两份 cell 计数数组和 face 读取窗口，得到批次工作布局。偏移、总数和范围验证继续与完整 count store 的规模核对。

运行时从已经解码的 count cache 生成批次描述，随后取得槽位和完整工作容量，再读取 ID 正文并构建输出。保留当前单记录提交推进方式。

### 11.3 独立分析

Params 只提供全局汇总，无法直接提供各批次实际分布。独立分析需要扫描三条计数流：unique vertex counts、cell face counts、face vertex counts。

使用有界读取游标同步消费计数，累计每个固定批次形状并保留容量峰值。无需建立完整 ID 数组，也无需进行数值属性解码。读取端复用现有流格式和外层解压设施。

只有实际执行多面体提交的请求需要这项扫描。普通数值和普通拓扑仍使用元数据计算。多面体计数扫描复杂度与读取的 cell、face 计数数量相关，不能将其描述为固定时间的纯元数据分析。

## 12. Observer 输出所有权

保留 `IDecodeTopologyBlockObserver` 当前允许调用方取得结果所有权的语义。

将 `DecodedConnectivityTopologyBlock` 的结果载体调整为可移动输出 owner 加只读数组视图。输出 backing 独立于输入和临时 backing，只移交结果区域。

移交时同步完成：

1. DataCodec 停止持有该结果存储
2. 从 DataCodec 受控容量和自有分配记录中移除该存储
3. 调用方取得数组及其实际释放责任
4. 输入、临时区域和剩余预约正常归还
5. observer 返回后归还槽位

所有权移交使用独立事件表示，不能把仍存活的调用方数组记录为已物理释放。调用方自行保留的队列不进入 DataCodec 在途清单。

当前 `iGamePreparedSurfaceDecodeAdapter` 同步消费块，下游 builder 已接受 span。适配集中在块载体、视图访问及相关测试，不引入后台队列。

## 13. 扩展最低运行额度分析

复用 `DecodeStoragePlan` 的帧依赖、属性依赖、宿主输出和已有会话处理。

在原有生命周期模拟中加入这些事件：

1. 必要长期目标建立
2. 字段和阶段缓冲建立
3. 单个块工作容量进入与退出
4. 阶段缓冲释放
5. 最终提交工作容量与长期目标释放

计算：

`minimumExecutionLimitBytes = max（当时必要存储 + 当时阶段缓冲 + 当前单块工作容量）`

长期存储峰值与最大块工作量可能出现在不同阶段，因此必须沿同一事件序列取峰值。禁止将两个独立最大值直接相加作为精确结果。

结果记录峰值所在帧、叶、阶段和块，以及该同一时刻的必要存储、阶段缓冲、块工作容量分项。所有分项服务于 `minimumExecutionLimitBytes` 的解释，不再维护旧口径的独立峰值和结果。

`AnalyzeAttributeStorage` 继续要求无在途任务。已有状态快照需要区分必要保留容量和明确可回收的 idle scratch；共享存储只计一次。对现有缓存的可释放性使用真实所有权规则，不通过占用估算推断。

适用条件必须写入接口说明：全内存路径、可选缓存可回收、既定依赖顺序、块可串行推进、调用方与第三方内存豁免。零工作量请求按其实际必要存储返回结果。

报告误差遵守已有验证口径。实际调度只使用当前工作单元的确定布局和真实预约账本，不使用审计结果，也不使用报告总量替代逐项准入判断。

## 14. 固定与自适应模式

两种模式共用 `UpdateLimits`、联合准入和释放通知机制。

- 固定模式在请求开始前确定上限，运行中保持该模式约定的目标
- 自适应模式由内部控制器发布后续目标变化
- 动态调节不增加面向用户或外部开发者的接口

降低内存目标后保留既有预约的有效性。后续正容量准入需满足新目标，已有任务继续使用已承诺容量并完成。不得为了立即达到新目标撤销任务的必要工作容量。

降低计算额度后已有计算完成，后续计算按新额度启动。提高额度后唤醒 driver 与工作线程。

在 `FlowSnapshot` 中增加下一工作单元需求、字节等待状态和等待时间。在自动控制器中落实：

1. 字节等待有独立诊断和观察项
2. 字节等待期间不因供给不足增加计算额度与槽位
3. 已排空且首个必要工作因字节不足等待时，允许根据可靠观测调整内存目标
4. 上述首块等待路径不依赖已有观察批次完成
5. 仍受最终容量上限、压力确认、恢复条件和等待超时约束

实际并行数由联合准入自然形成，不增加“剩余内存除以每线程内存”的线程数计算模块。

### 16.1 机制测试

- 相同输入和最低额度，在 1 份与较大计算额度下均完成
- 额度只容纳少量块时出现字节等待，实际活跃任务数量受限
- 提高额度后允许更多块在途，计算额度上限始终有效
- 队首刻意延迟、后续块先完成时能够按顺序提交并结束
- 等待期间发生容量归还、限额变化和取消，均被可靠唤醒
- 无可释放任务且下一工作仍超限时，明确失败或按自适应规则有限等待
- idle scratch 占用余额时，必要任务通过回收继续推进
- 运行中降低容量目标后，已有预约有效、后续准入遵守新目标
- 重复释放、跨预算转移、溢出和工作布局超范围进入 failure
