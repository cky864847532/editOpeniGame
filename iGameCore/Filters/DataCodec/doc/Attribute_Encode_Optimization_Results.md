# 属性编码优化逐项验收（2026-09-10）

## 范围与口径

仅优化 DataCodec 内部的属性读取、reference 数据准备、任务组织与提交。具体属性编码器、Libpressio、压缩参数、reference 选择规则、基础块大小保持不变。工作分支为 datacodec/dev。

采用现有 RelWithDebInfo、UCRT64 Clang、C++20、`-O2 -g -DNDEBUG` 构建。每次编译及执行先加载已核实存在的 CLion 环境脚本。输入为此前使用的 `car_3800W_Fluent_node_HDF5-0001.cgns`，10,571,784,552 B，131 个 Float64 单分量属性，默认无损及全部属性。

编码时间包含适配器和输出对象准备、编码、文件写出及诊断输出，CGNS 载入单独计时。每次完整运行还执行全属性解码和规模检查。输出文件保留在输入同目录，原始构建、测试和运行日志保存在仓库 logs 目录。保留每项测速程序快照，供交替对照使用。

本轮初始 Adaptive 基准为 27.550 秒，重复基准为 31.424 秒。第 1 项两次 Adaptive 为 30.153、28.805 秒。环境及自适应执行状态存在显著波动，以上数据尚不能证明该项收益。后续逐项速度比较统一使用 Fixed 8，算法配置保持一致，最终另行验证 Adaptive。固定模式的内存容量仍从当时环境确定，机器负载和文件缓存未严格隔离。

随后第 3 项一次运行出现 633.523 秒解码，其中 DecodeCommitStage.Topology 为 625.898 秒。系统事件日志确认该时段存在 Kernel-Power 506/507 新型待机进出事件，此前测试期间也有相同事件。上述未防止待机的速度数据不用于最终保留判定。各项程序快照随后按正、反顺序重新测量。

正式测速批次用 Windows SetThreadExecutionState 请求 `ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED`，避免自动待机污染墙钟。批次结束在 finally 中恢复调用前的状态，不修改系统电源配置。人工强制待机仍可能影响运行，实验完成后核对事件日志。

保持唤醒的第一轮 Fixed 8：原始程序 31.552 秒，第 1 项 30.111 秒，第 2 项 26.931 秒，第 3 项 23.214 秒。正序测试中未修改阶段也变快，最终判断需结合反序数据。

| --- | ---: | ---: | --- |
| 原始程序 | 31.552 | 26.855 | 对照 |
| 第 1 项 | 30.111 | 28.565 | 未确认收益，撤销 |

上述正反两轮没有新的 Kernel-Power 506 事件。第 3 项反序输出 SHA-256 与原始输出一致，全部实验完成编码、解码和规模检查。按反序原始程序与第 3 项比较，编码缩短 2.932 秒，约 10.9%；结果仍受设备负载和频率影响，不作为跨设备收益保证。

基准压缩文件大小为 2,204,353,773 B，SHA-256 为 `30E4A7F854DA89B097C38886B123F88707CCDD8D4E96821F0EDC553F05F80066`。第 1 项首次完整输出与该哈希一致。规模检查不等同于逐值比较；输出哈希用于证明相对于本轮基准的编码字节一致性。

## 逐项记录

1. 索引缓冲复用与固定宽度复制：NumericExecution 测试通过，已覆盖 Float32/Float64 位模式、尾块、provider/vector 排列及非法索引。Fixed 8 原始程序 28.733 秒，该项 29.011 秒，未确认收益，已撤销代码和对应实验测试，不提交。
2. 当前字段和 reference 共享索引窗口：NumericExecution 通过，输出哈希与基准一致。两次 Fixed 8 为 35.899、60.404 秒，随后原始程序为 29.991 秒。第二次包写出和首属性阶段也有明显等待，不能将全部差值归因于索引共享；没有确认收益，已撤销代码和实验测试，不提交。
3. 内存属性输入在现有 worker 内重排：保留，提交 `1c437925f`。仅从属性调用点启用；连续视图、内部内存排列可进入 worker，getter、文件排列及其他提供者继续在 driver 读取。DataCodec.All 与 NumericExecution 均通过，合计 16.71 秒；验证版本 Fixed 8 编码 25.478 秒、解码 8.001 秒，输出哈希与基准一致。针对性测试覆盖直接内存及 getter 路径、Float32/Float64 多分量、尾块、运行时额度变化、worker 读入失败与资源清理。
4. 属性块提交后的及时补充：两次 Fixed 8 编码为 25.651、25.812 秒，已提交的第 3 项对照为 23.485 秒；首次输出哈希与基准一致。未确认收益，已撤销，不提交。
5. reference schedule 复制及样本读取清理：正序候选 23.773 秒、对照 24.080 秒；反序候选 23.639 秒、对照 23.095 秒。首次输出哈希与基准一致，优势未重复出现，已撤销，不提交。

最终只保留第 3 项，不叠加第 1、2、4、5 项。第 3 项在保持唤醒的 Fixed 8 实验中依次测得 23.214、23.923、25.478、23.485、24.080、23.095 秒，波动范围 23.095–25.478 秒。上述测试包括编译后验证和候选对照，不将其中的最小值单独作为验收值。

最终清除候选后重新构建 FileBenchmark，构建成功。Adaptive 编码 23.943 秒、解码 7.705 秒，CGNS 载入 25.288 秒，exit code 0，规模检查通过。最终输出为 `car_3800W_opt_final_adaptive_20260910.igc`，大小和 SHA-256 均与本轮原始编码输出一致。该值单独报告，不与 Fixed 8 的结果混算收益。测速程序的最终算法代码对应 `1c437925f`，沿用工作区内此前的模块插桩及测速输出。
