# 线程控制实现约定

内存参数 `mode` 保留 Fixed、Adaptive、Unlimited 三种模式及原有计算公式。线程参数 `threadMode` 独立选择 Fixed、Adaptive，两者共用已有执行根、内部线程池和一个控制线程。

## 启动参数

| 线程模式 | 必需参数 | 执行语义 |
| --- | --- | --- |
| Fixed（默认） | `maxComputeThreads` 可省略 | 启动时确定计算线程上限，内存控制继续约束实际并发和槽位 |
| Adaptive | `targetCpuIdleRatio`，范围 `[0,1)` | 维持指定的全机 CPU 空闲比例；设备允许计算容量作为能力边界 |

Fixed 不接受空闲目标，Adaptive 不接受固定线程参数。Qt 提供独立模式下拉框并只提交适用的参数。旧配置默认使用线程 Fixed。

## 控制路径

Windows 使用 PDH 的 `Processor Information(_Total)/% Idle Time`，覆盖处理器组；逻辑处理器数量取全机数量。查询在控制线程上执行，每次顶层请求重新建立采样基线。当前其他平台不提供线程 Adaptive，参数解析直接报告不支持。

CPU 每 50 ms 采样，普通调节窗口为 200 ms。初始份额 `Q = clamp(H * (I - R), 0, Cmem)`，其中 H 为全机逻辑处理器数、I 为当前空闲比例、R 为目标空闲比例、Cmem 为原内存控制器发布的计算上限。

正常反馈按 `Q += clamp(K * H * (I - R), -step, step)` 调节，结果限制在 `[0,Cmem]`。空闲比例容差为 0.02，单轮最大步长为 `max(0.25,min(4,max(1,Q)*0.25))`。收缩名义 K 为 0.5，增长名义 K 为 0.125。增长需要待处理工作；内存门关闭、字节容量等待、显式输入或输出等待会阻止增长。

第一次存在计算工作且 `Q >= 0.25` 时启动短测量：200 ms 基线窗口后降低 `min(2,Q*0.25)`，再收集 200 ms。计算 `g = -H*(I1-I0)/(Q1-Q0)`，正的有限 g 用于更新 `Kshrink=clamp(0.5/g,0.025,1)` 和 `Kgrow=clamp(0.125/g,0.025,1)`。测量阶段期限为 1 秒；无效数值保留名义增益。后续正常额度调整也可被用于更新 g。

这里没有稳定工作类型、瓶颈归因、置信度或额外准确性验证。估计结果只表示观测响应。操作系统调度和长工作单元会影响观测，测量期限不构成可靠 K 的完成保证。持续 1 秒没有新鲜有效 CPU 样本进入现有 failure 通道。

## 执行与内存协调

实际并发为 `min(Cmem,ceil(Q))`。许可预算按 `Q*经过时间 - 活跃计算单位*经过时间` 更新，正余额最多保留 `Q*20 ms`。长任务形成的负余额会延后后继任务启动，从而支持小于一个线程的份额。这里计算的是许可占用时间。

普通工作和独占压缩包工作共用许可检查。独占包通过现有公开参数获得计算单位，内部库不增加新的分配或采样钩子。已运行工作在自身完成或已有取消检查处结束。

Q 为零时暂停新块和重阶段准入，保留控制采样、结果提交、消费和清理。待准入工作参与恢复判断，避免零份额无法恢复。内存门始终有效。CPU 更新不会重置内存观察批次，内存的原采样周期和公式保持不变。

worker 在队列前使用可唤醒的有界时间等待，取消和关闭均通知条件变量。计算中的 worker 不等待同一线程池的子任务。新请求重置 CPU 控制和许可余额，空闲线程可复用。

## 诊断与验证边界

现有运行日志增加 CpuControl 消息，包含请求编号、模式、有效并发、目标和观测空闲比例、Q、增益来源、g、两种 K、测量状态与耗时、调整次数、累计节流等待和许可余额。调试快照提供相同控制状态及 CpuThrottle 等待原因。日志导出失败遵循现有诊断缺失机制。

系统空闲比例是反馈目标，其达成取决于外部负载、数据供给和工作单元长度。控制只延缓 DataCodec 自己的工作单元，不改变其他程序的调度。当前验证范围为 Windows，包括策略数值测试、许可预算测试、六种内存和线程模式组合的编解码回环、队列顺序、独占工作、取消、请求复用及 Qt 参数持久化。
