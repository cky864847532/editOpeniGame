# DataCodec 桥接整改实施记录

本记录对应 `DataCodec_Bridge_Audit.md`，保留原审查报告作为整改依据。

## 已实施的接口与职责调整

- 核心解码结果采用 `DecodedData`、`DecodedLeaf`、`DecodedBuffer` 和具体 `DecodedFrame`，携带标量类型并拥有存储。交付结果与执行资源、缓存和显式会话分别持有。
- 删除公开解码直写 adapter、外部组装器、拓扑 observer 和 ObserverOnly 选项。内部解码存储协议收进 Workflow，原生对象由 iGame 与 VTK 消费完成结果后组装。
- 几何按原始 Float32/Float64 类型解码；非连续整数属性通过原始类型字节 getter 读取。iGame Points 的表示仍为 Float32，接收 Float64 几何时明确报错。VTK 接收 Float64 并保持其精度。
- 编码输入共享持有业务 adapter 及访问状态；压缩输入统一为路径、共享内存或 BrowserFile。输入容量观察独立报告有效字节、已知容量与未知容量区域，同一分配的重叠视图去重。
- `EncodedBuffer` 仅持有结果字节及释放状态。iGame 的 FlatArray、ElementArray 接管完成数组；VTK 数组持有完成存储，拓扑转换直接写入最终 VTK 数组。
- 文件读写由核心管理，Windows 使用文件映射，POSIX 实现 mmap，范围操作使用有界窗口。文件输出先完成同目录临时文件，刷新、关闭后发布；多帧输出由核心执行发布和失败回滚。
- 普通 Reader 在按需属性模式交付显式属性会话；播放属性请求通过帧身份和会话执行。缓存关闭或清理后，当前交付对象仍可使用。
- Writer 的直接文件写出模式退出缓冲区生成与保存合同，避免空缓冲区覆盖完成文件。
- Wasm 原始数据桥接和模型注册表迁入 Example。抽壳、表面复用、持久化及表面任务调度归 Example；表面命中后声明展示能力，并保留原始输入用于恢复原始数据。
- 进度回调异常隔离；包头错误保留结构化错误码与版本信息；阶段分类使用枚举；帧身份保留 uint32 范围。

## 验证范围

本机工具链：CMake、Ninja、MSYS2 UCRT64 Clang/LLD。构建包含 Qt 和 VTK。

回归覆盖类型保真、输入共享寿命、输出接管与最终释放、会话关闭、取消交接、缓存与按需属性、Writer 组合调用、文件窗口与发布、Wasm 注册表恢复以及公开 API 接入。

最新回归结果：22/22 CTest 通过，耗时 18.76 秒。构建成功的目标包括核心测试、公开 API 测试、iGame 测试、Qt 资源控件测试、VTK 所有权测试和 VTK 往返示例。

命令行编码/解码示例、文件基准程序与序列基准程序也已编译链接成功。本轮未运行真实数据性能基准。

本轮新增验证包括：

- 共享输入区间去重、独立分配分别计数、未知容量保持未知、越界容量拒绝、持续会话保留原输入观察值
- VTK Float64 精度与几何/属性同址接管，最后一个 VTK 引用释放完成存储
- 文件扩展、第二个映射窗口、第二个映射刷新及最终文件刷新故障，失败后原目标完整、临时文件清理
- 不完整输入、版本不支持与错误格式的结构化错误通过 Wasm 注册表、播放入口及 iGame 序列桥接保留
- 原始数据恢复期间注册表清空，恢复操作取消并避免发布到失效模型

`git diff --check` 通过。Wasm 页面主入口的恢复、保存能力检查与错误输出经过静态核对，未纳入上述本机构建结果。

## 平台与测量边界

- 本机测试执行 Windows 文件映射分支；POSIX mmap 分支需要在 POSIX 平台运行验证。
- Wasm 桥接与注册表参加原生回归测试；Emscripten 编译、Asyncify 页面操作和浏览器 File/OPFS 行为需要浏览器平台验证。
- 原生测试用数组地址和 weak owner 检查复制与释放。真实大数据集的进程峰值、跨 JS/Wasm 复制量和交互延迟尚未测量。
- 核心自有预算、外部输入观察、调用方长期持有的结果容量分别表达，核心额度不等同于进程总内存。
- R10 的统一异步 API 为报告中的可选项，当前沿用宿主后台调用与核心内部执行资源。
